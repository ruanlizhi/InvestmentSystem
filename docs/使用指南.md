# 第一版使用指南

## 启动

需要 Bun 1.3.11 或更新版本。首版无外部运行依赖；开发静态检查需要 `bun install` 安装锁定的开发依赖。

```bash
bun install --frozen-lockfile
bun run build
bun run demo
```

公开版通过 bun run demo 启动于本机 4318 端口，读取 src/public-snapshot.json 中经授权的固定快照，不读取私人配置或旧虚构演示工作区。私人版仍使用 4317 端口。两版共用界面，当前业务内容一致，本机来源路径在公开版改为文档名称。后续私人更新不会自动同步公开；旧虚构演示工作区保留，不作覆盖。

私人使用先创建仓库外工作区，再启动：

```bash
bun run cli init --workspace /absolute/path/to/private-runtime
bun run start --workspace /absolute/path/to/private-runtime
```

Windows 也可传入 `E:\somewhere\private-runtime`，或设置 `INVESTMENT_WORKSPACE`。不要把数据放入软件目录。服务仅监听本机回环地址，不是面向公网的多用户服务。

## 在对话中维护内容

网页是只读工作台，更新通过 CLI 完成。所有输入由当前授权的本地助手整理，不内嵌调用外部模型。

```bash
bun run cli show --workspace <工作区>
bun run cli search --workspace <工作区> --query <关键词>
bun run cli show --workspace <工作区> --id <记录ID>
bun run cli apply --workspace <工作区> --file <私人批次JSON> --expect 1 --reason "保存本次讨论确认的内容"
bun run cli summary --workspace <工作区> --id <标的或预案ID>
```

先读取 `revision`，再用该数字作为 `--expect`；冲突时重新读取并核对，不覆盖别人刚保存的内容。批次 JSON 放私人目录，结构为 `{"records":[记录,...]}`。单批次最多 500 条，引用的对象先于引用者写入。

网页右上角刷新获取最新数据。预案的“带到对话中讨论”显示可复制摘要；复制失败时可在文本框手工复制。搜索作用于当前列表，进入不同页面会重置搜索与状态筛选。

## 记录格式

每条记录包含以下字段；未知文本填空字符串，未知日期和金额用 `null`，不填假数值。

```json
{
  "id": "principle-example",
  "kind": "principle",
  "title": "示例原则",
  "body": "此处填写已确认的原则内容。",
  "status": "draft",
  "date": "2026-01-01T00:00:00.000Z",
  "source": "本次本人输入；请换成实际出处",
  "identity": "opinion",
  "refs": [],
  "fields": {"category": "研究方法", "boundary": "待明确"}
}
```

- `status`：draft / active / review / retired。
- `identity`：fact / opinion / inference / decision；事实记录不自动代表已经核验。
- `refs`：精确引用，例如 `{"id":"principle-example","version":1}`。
- 日期均用 UTC ISO 毫秒格式，页面按浏览器本地时区显示。内容日期和实际录入时间分开保存；补录不能证明事前已准备。
- 可变记录使用同一 ID 写入新版本；版本号和录入时间由程序生成。

|kind|fields 必填内容|
|---|---|
|principle|category、boundary|
|asset|symbol、aliases（字符串数组）、direction、basis、tam、capture、moat、feedback、falsifier、unknowns；可选 priceMinor、currency、priceDate|
|evidence|assetId（一般资料可为空）、stance（support/challenge/neutral）、locator、publishedAt（可 null）、dataPeriod、verified（布尔）|
|plan|assetId、direction、observation、falsifier、buy、sell、preparation、reviewAt（可 null）、checkState（unmonitored/pending/checked）|
|decision|assetId、plan（版本引用）、action（buy/sell/wait/research/rebalance）、discussionAt（可 null）、rationale、validation、missingPreparation|
|account|currency（三位币种）、cashMinor（整数或 null）、holdingsKnown（布尔）、positions（持仓数组）|
|flow|accountId、amountMinor（带正负号的整数）、reason|
|trade|accountId、assetId、plan（版本引用）、decision（版本引用或 null）、side（buy/sell）、quantity、priceMinor、feeMinor、missingPreparation|
|review|target（决策或成交的版本引用）、judgment、execution、outcome、next|

期初持仓格式：`{"assetId":"asset-id","quantity":100,"costMinor":120000}`。数量最多六位小数；账户 cashMinor、priceMinor、feeMinor、costMinor 按币种最小单位记账（首版用于两位小数币种）。期初账户、资金流、决策、成交及复盘不可覆盖，补充复盘使用新 ID。

## 资金与实际操作

先核对账户期初日期、现金、持仓，再按账户时间顺序追加资金流和成交。已知现金不足、超额卖出或倒序录入会被拒绝。期初持仓未知时拒绝成交核算；现金未知时允许保存但余额仍显示未知。

成交必须关联预案。缺少决策或事前讨论时写明 missingPreparation，系统不补造历史。决策内容与成交的标的、方向和预案版本必须匹配。拆单可关联同一决策；软件不提供下单接口。

市值采用手工价格及其日期，缺少价格或币种不匹配时显示待补充；不同币种不合并总值。剩余成本使用移动平均方式，仅作记账辅助，不是税务口径。首版不计算真实收益率或汇率换算。

## 备份与恢复

每次成功修改前保存旧版到工作区 `backups`。软件只接受 schemaVersion 1，遇到新版本或损坏内容停止，不自动重建空数据。当前没有需要运行的格式升级脚本。

```bash
bun run cli restore --workspace <工作区> --file <已校验备份.json> --expect <当前修订号>
```

恢复也保存恢复前快照，并产生更大的修订号；不能跨演示与私人模式恢复。以上命令用于当前 state.json 可读取的正常恢复。若当前文件损坏，先停服务、完整复制工作区，再在新工作区校验备份，避免破坏唯一证据。

写进程异常退出可能留下 `.write-lock`。确认没有运行中的写入进程后再处理锁，不自动删除未知锁。备份不是异地备份，重要私人数据仍需独立备份。

## 当前边界

首版记录并展示证据，不自动监测市场或判定证伪。没有自动抓取、在线模型、实时行情、压力测试及推理方法独立评测。网页验收状态以执行结果为准，不能从构建成功推定外观通过。
